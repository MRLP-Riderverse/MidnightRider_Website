# Project policy — MidnightRider_Website

This policy keeps the website repository useful as a public code mirror while private thinking stays in the user's Notecore project.

## Information boundaries
- Raw ideas, personal reflections, and capture-inbox material belong in `~/Documents/Notes/notecore/projects/websites/MidnightRider/`.
- Do not copy `MidnightRider.txt`, recap files, or `session.json` into this repository.
- Transfer an idea into this repo only when it is intentionally selected for public-safe project documentation or implementation. Preserve the original Notecore text as authored.
- Do not add credentials, wallet seed phrases/private keys, private contact details, or sensitive personal data. Public wallet addresses or identity details require deliberate owner intent before publication.

## Repository stewardship
- Keep GitHub as the versioned mirror for site code and selected public-safe project artifacts—not as the capture inbox or sole record of personal thought.
- Review `git status`, staged paths, and diffs before every commit. Stage narrowly; avoid adding generated, temporary, private, or unrelated files.
- Do not commit or push without explicit approval from the owner.
- Prefer portable static assets and standards-based code. Avoid platform-specific assumptions unless documented and reversible.
- Preserve a clear distinction between this personal site, Riderverse commerce, and Acadie.sol community work.

## Design and implementation
- Start with visitor needs and selected content before choosing page architecture or effects.
- Prefer a fast, legible, responsive experience. Treat splash screens, motion, and decorative effects as optional and ensure they do not block access or harm accessibility.
- Purple, green, and sable are exploration notes, not a finalized palette. Do not infer final colors or branding from them.
- Keep decisions and TODOs concise, dated when useful, and public-safe. `todo/` is for actionable work; `logs/` is append-only.
